Over the past few months, I have been thinking about how large language models, or LLMs, use language patterns learned from text written at different times. A word can have more than one meaning, and a product name can refer to something that has changed since the model learned about it. The answer a model produces may not match what I mean when I ask.

I use "meaning drift" for that practical mismatch between the answer and the meaning I intend. But there are different problems inside that phrase: language can change, the model's information can be old, or my question can leave the intended meaning unspecified. Distinguishing them matters when deciding what context to provide.

## What the model does with your words

This is how I explain a text-generating transformer model. The tokenizer associated with the model breaks text into tokens, and the model maps token identifiers to learned vectors of numbers. Different models can share a tokenizer; there is not necessarily a separate one for every provider.

The numbers go through the transformer. Attention combines information from tokens in the available context, while feed-forward layers apply further learned transformations. Matrix multiplication is a large part of this computation. The learned relationships are represented in the model's parameters, not in a dictionary of fixed meanings for each word.

At each generation step, the model produces scores for possible next tokens. A decoding procedure selects what comes next: it may choose the highest-scoring token or sample from a probability distribution, with settings such as temperature, top-k and top-p affecting sampling. Not every service exposes the same controls.[^generation] In ordinary autoregressive generation, the selected token becomes part of the input for the next step.

The answer therefore depends both on what the model learned and on the context supplied for this request. That context can include information the model did not have during training.

## Language is not born out of rules

Language itself has a nuance: its use is not fixed by a rulebook. People use it in communities, and the meanings and conventions change. Usage guides describe and assess those conventions; they do not stop the language from changing.

Bryan Garner's *Garner's Modern English Usage* is one reference I use when thinking about changing usage.[^garner]

## What the training data carries

During the LLM training phase, I presume, the model is trained on language patterns created at different times, with many English words taking different meanings over those times. Human societies in different geographies also interpret words, and combinations of words (phrases), in different ways.

Training can expose a model to different uses of the same word, but that does not mean it learns every use or preserves each one accurately. Its stored knowledge also does not update just because new material appears online. An AI system can retrieve newer information and add it to context; that is different from changing the model's trained parameters.

## Meaning drift

Historical changes in word meaning are one part of the problem. The word "nice", for example, has older senses such as "foolish" or "silly", quite different from its familiar present-day sense of "pleasant".[^nice] That illustrates language change; it does not show that a particular model is likely to choose an obsolete sense in an ordinary modern conversation.

An example from my own use involved Omarchy, a Linux distribution based on Arch Linux.[^omarchy] When asked about Omarchy, the model referred to an older version rather than the latest one. This is more directly an example of outdated version information than of a word changing its meaning. The product name stayed the same, but the answer concerned a different release from the one intended.

I suspect that sparse coverage can make some subjects harder for a model to answer accurately, but this example does not establish that as the cause. More popularity would not guarantee that a particular model had learned the latest release, or that a system had retrieved the right documentation. The relevant question is which version the answer is based on and how that was established.

An instruction such as "always use the latest version" states what I want, but it does not supply current release information or guarantee that the system can obtain it. A more useful request identifies the version, supplies its documentation or asks a system with retrieval tools to check the current release and name its source. Context engineering helps specify the question; checking the sources and the answer is still necessary.

## What I ask of an AI system

In my use case, I want agentic AI systems to communicate back, or write, in words, phrases and sentence lengths that carry concrete meaning and information to the maximum possible extent, and that stay honest to the current times at which the model or AI system is responding.

This doesn't have to mean an AI model should be restricted to using words or phrases that only have concrete meanings, with a strong assumption that most human societies understand them as concrete, without meaning drift. Language keeps changing, for the reasons above.

What I ask for is only for my use case.

In the Omarchy example, the practical failure was answering about an older release without resolving which release the question meant. Stating the version and the source would make that mismatch easier to identify.

I put this to AI agents in a guide that I am writing for them. The guide contains no AI-generated text; I am writing it with keyboard typing and my own thinking, mostly as a lightly constrained train of thought with minimal editorial changes. I use an unusual layout size and a fixed-width font. Those are presentation choices, not a guarantee that an agent receives or interprets the layout as I see it. The instructions themselves have to convey how I want the system to work.

## What I can control

I cannot resolve changing language, missing knowledge and an ambiguous question with a single instruction. I can make the intended meaning more explicit, provide relevant information and ask for the version and sources behind an answer. That is the part I work on through context engineering and through guides like the one I am writing for agents.
